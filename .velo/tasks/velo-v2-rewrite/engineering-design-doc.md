# Engineering Design — Velo V2 resumable delivery pipeline

> Version: 1.3 — 2026-08-23
> Status: Pending approval after focused design-review revision

## Assumptions (flag if wrong)

- Runtime parity → Claude Code and Codex may use different pinned adapters, but must emit the same normalized contract events and outcomes; flag if identical implementation is required.
- Enforcement floor → role isolation depends on a Trusted Broker plus Linux containers; native Claude/Codex subagents alone are insufficient.
- Availability → when capability proof is absent, V2 permits only Ask without repository tools and protected draft save; Pair, Run, and Auto are unavailable.
- Credentials → V2 v1 does not expose repository or application secrets to roles; flag if builds requiring such secrets must be supported initially.
- Metadata boundary → drafts, keys, run state, bundles, and archives live outside every repository with owner-only access.
- PR-ready → the validated working-tree manifest is complete; V2 v1 never performs commit, push, PR creation, arbitrary network, or other external work effects.
- V1 boundary → V1 is read-only evaluation evidence; active V1 work is never claimed or rewritten.

## Decisions

| # | Decision | Rationale |
|---|---|---|
| D1 | Put a closed reducer behind a Trusted Broker; all four behavioral roles are untrusted sessions and EM can request, but never directly write, transitions. | Four understandable roles do not make model processes trusted state custodians. |
| D2 | Run provider CLIs as Untrusted Role Sessions and execute repository tools in separate Isolated Tool Workers through Artifact Ingress. | Native subagents share host access; provider differences must stop at an adapter boundary. |
| D3 | Make M1 a hard feasibility gate for both providers and the host; no later milestone or Pair/Run/Auto enablement proceeds on partial proof. | Safety claims are invalid if either adapter can bypass the boundary. |
| D4 | Use a normative, total reducer table with exactly-one-row matching and crash-atomic immutable segments. | State authority, replay, and recovery require one executable source of truth. |
| D5 | Require read-only proposal, kernel classification, mutation grant, bound mutation session, and actual-delta verification before assertions. | Declared intent and observed repository effects are separate gates. |
| D6 | Product submits a candidate; the Broker validates, canonicalizes, renders, and freezes approved bytes as plan N, and only material change creates N+1. | Approval must authorize one authoritative object the human actually saw. |
| D7 | Separate guided and Auto review, require a validated PR-ready manifest, and leave all commit/push/PR/network effects outside V2 v1. | PR-ready needs adversarial proof, not ambient credentials or hidden shipping authority. |
| D8 | Predeclare versioned parity, replay, and pilot scorecards; replacement cannot waive safety, approval, or receipt invariants. | Migration evidence must be measurable before results are known. |

Shape: see `architecture.md`.

## Exact enforcement floor and dependencies

The baseline bundle pins macOS 15.6.1 arm64, Node 22.12.0, npm 10.9.0, Git 2.50.1, Claude Code 2.1.239, Codex CLI 0.148.0, Docker client/daemon 29.6.2 with API 1.55, an OCI image by digest, JSON Schema validator and lockfile digests, and a Broker signing key held by the OS key store. Other versions are different bundles and must repeat M1. The current host has the CLIs and Docker client but no reachable daemon, so capability is presently unproven.

The Trusted Broker is an owner-only local service and sole kernel writer. Each Untrusted Role Session runs in a fresh non-root container with read-only rootfs, dropped capabilities, no-new-privileges, seccomp, PID/memory/time limits, an empty working directory, no host/config/key/state/repository mounts, and only private connections to Artifact Ingress and a destination-bound provider proxy. A per-session network namespace has one veth to that proxy; the proxy authenticates the Broker-created namespace/cgroup, fixes provider/model/session, validates request shape, injects the OS-key-store credential, and permits no other destination. This provider transport is infrastructure, not a role capability or work effect. No credential or reusable proxy token enters the role container, and no Docker socket is mounted.

Claude sessions use `claude -p --bare --no-session-persistence --strict-mcp-config --disable-slash-commands --no-chrome --permission-mode dontAsk --tools "" --allowedTools mcp__velo_ingress__invoke --output-format stream-json --json-schema` with only Artifact Ingress configured. Codex sessions use `codex exec --ephemeral --ignore-user-config --ignore-rules --strict-config --sandbox read-only --json --output-schema`, explicit `mcp_servers.velo_ingress` config only, `shell_environment_policy.inherit=none`, and an empty container workspace. Any inherited tool, config, environment secret, rule, hook, MCP server, writable mount, or direct egress fails M1. Official mechanisms are documented in [Claude CLI reference](https://docs.anthropic.com/en/docs/claude-code/cli-usage), [Codex sandboxing](https://learn.chatgpt.com/docs/sandboxing), and [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode); M1 verifies behavior rather than trusting flags.

Artifact Ingress exposes schema-bound reads, searches, proposal submission, patch application, assertion execution, and handoff/verdict submission. It launches a separate no-network Isolated Tool Worker per directive: Product, EM Ask, Reviewer, and Builder proposal get a read-only repository mount; only a mutation-granted Builder worker gets one dedicated worktree read-write. General repository/application secret capability is unsupported in v1. A plan needing one is unexecutable and remains Pair-paused.

Repository reads and searches deny `.git/**`, `.env`, `.env.*`, `**/*{credential,credentials,secret,secrets,token,tokens}*`, `**/*.{pem,key,p12,pfx,jks,keystore}`, `**/.{npmrc,pypirc,netrc,git-credentials}`, `**/{.ssh,.gnupg,.aws,.azure,.claude,.codex,.kube,.docker,.config/gcloud}/**`, `**/{settings,config}.local.{json,yaml,yml,toml}`, `**/*auth*.{json,yaml,yml,toml}`, and every `git check-ignore` match before returning even a path. Credential/key/runtime-config patterns are immutable denies; an otherwise ignored path may be exact-path approved only in plan N and the approval render. Artifact Ingress opens from a pinned repository directory descriptor with `openat2` beneath/no-magic-link/no-symlink constraints, verifies the same descriptor is a regular file on the allowed mount, and reads that descriptor once—never a re-resolved path. Before any bytes reach a role, type/encoding limits plus key signatures, known-token patterns, and entropy scanning run. Safe planned redaction returns `READ_REDACTED` with a report; a deny, binary/unknown encoding, scanner uncertainty, or suspicious remainder returns `READ_POLICY_DENIED` or `READ_SECRET_UNCERTAIN` with no content and raises a same-plan tripwire.

The Trusted Chooser is a Broker-owned companion UI over a mode-`0600` Unix socket. The Broker validates peer effective user ID, the companion validates the Broker signature with an OS-key-store public key, and the callback consumes one nonce; model tools and provider sessions cannot connect. It is the only path for protected draft save, approval, takeover, export, and abandon. M1 must prove this channel plus container/mount isolation, broker/socket/key denial, proxy destination binding, provider-session identity, read-only Product/Reviewer/Builder-proposal access, read-path secret denial, mutation-grant enforcement, symlink/realpath containment, network denial, credential non-exportability, and atomic storage on both adapters. One failure emits `CAPABILITY_UNPROVEN`; no run is created and all later milestones are blocked.

## Closed kernel API and capabilities

| API | Authorized caller | Authority |
|---|---|---|
| `saveDraft`, `approvePlan`, `chooseRecovery`, `takeOver`, `exportRun`, `abandonRun` | Trusted Chooser only | Signed user act over exact displayed bytes/action; never a transcript claim. |
| `createRun`, `claimRun`, `prepareDirective`, `requestAdvance`, `raiseTripwire` | EM Role Session through Artifact Ingress | Propose kernel work under run/session capability; kernel recomputes guards and next state. |
| `submitPlan` | Product Role Session through Artifact Ingress | Submit typed plan/done/surface/skill artifacts; no transition or mutation. |
| `submitProposal`, `submitActionResult`, `submitHandoff` | Builder Role Session or its bound Isolated Tool Worker | Only the prepared directive, proposal/grant, plan, session, cursor, and evidence hashes. |
| `submitVerdict` | Reviewer Role Session | Only its cold-session inputs and verdict; peer verdicts are unreadable. |
| `readProjection`, `requestTool` | scoped Untrusted Role Session | Redacted least-privilege projection/tool; no kernel socket, raw state, keys, or credentials. |
| `commitEvent`, `commitObject`, `applyTransition`, `issueCapability` | Trusted Broker kernel only | Sole writer; no public endpoint or role credential exists. |

Every capability binds run, role, provider/session identity, bundle and adapter digests, plan version, directive/cursor, operation set, nonce, and expiry. EM owns every advance directive; the kernel consumes it only after the required role, Broker, or Trusted Chooser evidence arrives. Thus the Broker enforces transitions without becoming a fifth behavioral role.

## Atomic records, effects, and retries

Objects stage on the target filesystem: create exclusive temporary file, write and file-fsync, verify digest, rename atomically, then directory-fsync. Events reference committed objects and use the same sequence; a final commit marker is file-fsynced, renamed, and directory-fsynced. Only the contiguous hash-linked marker chain is visible. Orphans are quarantined, never inferred. Checkpoints and JSONL are disposable verified projections.

Every role call or effect first commits `DIRECTIVE_PREPARED` with action cursor, canonical payload digest, actor/session, expected effect, grant, probe, and replay class. `ACTION_RESULT` and `HANDOFF_SUBMITTED` bind that directive, payload digest, session, result, and evidence. Repeating the same directive ID plus identical canonical payload returns the original committed result without appending or advancing; the same ID with different content returns `IDEMPOTENCY_CONFLICT`, appends nothing, and pauses. Missing terminal proof is `indeterminate`: only a directive-specific probe may reconcile completed/not-started; insufficient or conflicting proof needs Trusted Chooser adjudication, never automatic respawn/replay.

A corrupt committed chain freezes the original run. It resumes only after hash-identical archived bytes restore the chain; otherwise continuation creates a new run whose genesis records `recoveryOfRun`, last verified commit, corrupt-chain digest, and decision receipt. Sequence forks inside the original run are forbidden.

## Frozen plan, approval, skills, and two-phase build

Product's candidate contains repository/base identity; structured allowed create/modify/delete and protected path sets; local capability grants; deliverables, exclusions, risk, assertions and evidence; review policy/rework cap; retention; PR authorization state; and an ordered `SkillSet`. Each skill entry carries catalog ID/path, content digest, role eligibility, precedence, reason, and declared exclusive-conflict keys. Broker validation rejects a missing catalog entry, digest mismatch, role ineligibility, duplicate/exclusive conflict, or unresolvable schema error. Precedence—kernel safety > role contract > default bundle > additions in order—resolves instruction overlap only; it never cures an explicit exclusive conflict. The Broker canonicalizes the valid candidate, injects digest-verified content in order into Builder/Reviewer sessions, and parity fixtures compare both adapter renders. Skills never create a behavioral role.

Product can submit candidates but cannot write canonical plan/render objects. The Broker schema-validates, normalizes references and ordering, canonicalizes UTF-8 plan bytes, derives immutable render bytes, and stages both by hash. The Trusted Chooser displays those exact bytes, or an owner-only link to them, covering scope, surfaces, local capabilities, exclusions, assertions/evidence, skills, review policy, and unsupported ship effects. Its one-time callback binds OS user, run, N, render length and exact bytes, plan/render hashes, nonce, and expiry. Only then does the Broker freeze the staged objects. Invalid or stale approval is rejected before append and remains `PAIR_APPROVAL`; it never enters recovery or Run. The already-prepared EM directive consumes valid approval atomically and starts `RUN_PROPOSE` without a second gate.

Builder first submits `ProposedChange` from a read-only Builder Role Session: base tree, path operations and realpaths, effect/capability requests, deliverable/assertion/evidence mapping, and risks. The kernel comparator alone classifies against plan N. Unclassifiable or material delta enters Product for N+1; a match issues a digest-bound mutation grant and fresh Builder Role Session. After mutation, the Broker hashes the actual tree/diff and compares operations, symlink targets, effects, and blobs to both proposal and grant. Mismatch revokes custody and enters recovery before any assertion.

V2 v1 supports only repository reads, isolated-worktree writes, assertions, evidence, manifest assembly, protected draft/state persistence, and user-authorized local lifecycle archive/export/purge. It does not execute git commit, push, PR creation, package download, arbitrary network, webhook, deployment, or other external work effects. Such requests are rejected as `EXTERNAL_EFFECT_UNSUPPORTED`, and no network grant can appear in plan N. `PR_READY_MANIFEST` records commit/push/PR authorization only as `not_requested` or `pending`; after terminal readiness the user may execute them with separately authorized tooling outside V2. That external result is not required for `PR_READY` and cannot rewrite the terminal run.

## Claim, takeover, recovery, and abandon

A protected claim is a compare-and-swap record over run, claim generation, Broker instance, OS user, adapter/provider session, bundle/policy digests, issued/expiry times, and prior commit hash. Exactly one claim may be active. A concurrent request returns `CLAIM_CONFLICT`, appends nothing, reveals only owner/age, and starts no session or worker. Lease expiry or lost heartbeat marks the claim interrupted and blocks ingress; it never silently transfers ownership.

The Trusted Chooser offers resume current owner, transfer, redacted export, or abandon. Resume/transfer first reconciles every prepared directive using its probe; `indeterminate` requires user adjudication. Transfer then blocks ingress, revokes mutation/lifecycle grants, terminates Isolated Tool Workers, inventories base/tree/diff plus staged/untracked path hashes, closes provider sessions, invalidates role/session capabilities and the old claim, commits the takeover receipt, and only then issues the next claim generation. No new worker starts before that order completes.

PR-ready and abandon use the same revocation/inventory order, commit the terminal event, then release the claim. The protected run state, pinned bundle, sealed read-only worktree, and redacted change inventory remain through retention. An interrupted nonterminal run may resume or transfer; a terminal/abandoned run may inspect or user-authorized export only. Continuing abandoned work requires a linked recovery run; the original is never reopened.

## Normative reducer contract

Canonical states are `PAIR_PRODUCT`, `PAIR_APPROVAL`, `RUN_PROPOSE`, `RUN_MUTATE`, `RUN_VERIFY_DELTA`, `RUN_ASSERT`, `RUN_REVIEW_GUIDED`, `RUN_REVIEW_AUTO`, `RUN_MANIFEST_ASSEMBLE`, `RUN_MANIFEST_VALIDATE`, `PAIR_RECOVERY`, `PR_READY`, and `ABANDONED`; Ask has no run state. The versioned `reducer.v1` artifact serializes rows with required fields `id, source, authorizedActor, event, guard, directive, effect, destination, versionConsequence, retrySemantics, recoveryAction` and the table below is its normative content.

Closed reason sets are: `SAME_PLAN_TRIPWIRE` = stale/missing/incompatible receipt, auth failure, action failure, indeterminate effect, idempotency conflict, read-policy deny/secret uncertainty, unsupported external effect, assertion failed/unavailable/unsafe/flaky-exhausted, evidence missing/redaction/limit failure, actual-delta mismatch, guided blocker/cap, Auto quorum failure, review timeout/identity failure, policy unproven, unsafe mutation, or manifest assembly failure; `MATERIAL_TRIPWIRE` = scope, approved surface, local capability, risk, done contract, or required-evidence change, or unclassifiable delta; `FATAL_TRIPWIRE` = bundle mismatch, persistence fault, or corrupt chain. `MANIFEST_STALE_OR_INVALID` causes are stale basis, out-of-scope diff, stale assertion/review, unproven deliverable, blocker present, or invalid authorization claim. No adapter may mint another reason.

R18 or R20 creates an immutable `RecoveryRecord` bound to reason, origin state, approved N/event hash, implementation/evidence hashes, reconciliation requirements, and exactly one resume state already present in N's authorized history. Receipt/auth/action/idempotency faults resume their recorded origin after reconciliation; actual-delta/unsafe-mutation, assertion/evidence, and fixable review findings resume `RUN_PROPOSE`; review timeout/identity faults resume the same guided/Auto review state; manifest assembly resumes `RUN_MANIFEST_ASSEMBLE`; manifest basis/diff, assertion, review, deliverable/blocker, and authorization causes resume `RUN_VERIFY_DELTA`, `RUN_ASSERT`, the recorded review state, `RUN_PROPOSE`, and `RUN_MANIFEST_ASSEMBLE` respectively. A reason that requires any contract/surface/risk/evidence change cannot create this record and uses R21 to `PAIR_PRODUCT`. `PAIR_RECOVERY` can consume only its record; it has no generic Builder or Product exit.

| R21 | any Run state or `PAIR_RECOVERY` | EM; `MATERIAL_TRIPWIRE` | reason is material or delta unclassifiable | revoke grants/sessions; preserve evidence | `PAIR_PRODUCT` | create N+1 draft | exact returns tripwire | only exact N+1 approval can re-enter Run |

| R23 | any nonterminal | EM; `DIRECTIVE_PREPARED` | action legal in source and cursor/session unique | commit prepared directive | same source | unchanged | exact returns directive | conflict: reject/no append; Run may invoke R20 |
| R24 | any nonterminal | EM; `CLAIM_REQUESTED` | no active claim, or trusted takeover with every pending directive reconciled; chain/bundle/policy/session match | CAS next generation only after ordered revocation/inventory | same source | unchanged | exact returns claim | concurrent reject/no append; interruption offers resume/transfer/export/abandon |
| R25 | any nonterminal | EM + Trusted Chooser; `ABANDON` | current claim, reconciled directives, exact displayed inventory | block ingress; revoke/inventory; commit terminal; release claim | `ABANDONED` | version unchanged | exact returns terminal | inspect/export only; continuation is linked run |
| R26 | any nonterminal | any ingress; `UNCLASSIFIED_CONDITION` | condition cannot normalize | block ingress; append no business event; freeze source | same source frozen | unchanged | no replay | classify to exact R20/R21/R22 event or abandon |

The event and reason enums are closed. Schema generation must prove every state/event/actor/guard outcome has exactly one row and every destination is declared. Runtime zero-match rejects the input without append or advance as `UNHANDLED_EVENT`; multiple-match freezes as `AMBIGUOUS_REDUCER`. Tests execute every row's success, false-guard recovery, exact retry, conflicting-payload retry, and crash boundary, plus mutation tests that remove or overlap a row.

## Review, PR-ready, evidence, and replacement gate

Guided Run uses one cold Reviewer Role Session; pass with no blocker advances, bounded non-blocking findings re-enter proposal, and blocker/cap/timeout/identity failure enters R20's reason-bound Pair recovery. Auto always uses three cold Reviewer Role Sessions with distinct provider/context/container identities and hidden peer verdicts; three terminal results, at least two passes, and no blocker are required. Verdicts bind plan, implementation, input-manifest, session, adapter, and bundle hashes.

`PR_READY_MANIFEST` binds base commit and working-tree tree/diff basis; proposed title/body; scoped operation and blob hashes; every PRD deliverable mapped to assertion/evidence/review proof; exclusions; findings; runtime/policy/plan/skill digests; and separate commit/push/PR authorization fields. V2 v1 validation accepts only `not_requested | pending`; `granted | consumed` are reserved for a future effect contract and are rejected. Validation re-hashes repository and evidence. Stale/invalid same-plan candidates receive the cause-bound R18 record; material deltas use R21.

Before persist, Artifact Ingress bounds, normalizes, secret-scans, and redacts evidence; uncertainty pauses. Defaults are 1 MiB per stream, 8 MiB per object, and 256 MiB per run. Objects carry classification, producer/session, plan/implementation hashes, freshness, redaction report, and retention. State is owner-only outside Git; exports are explicit signed redacted manifests. Terminal archive/purge is a prepared user-authorized effect; active runs/bundles are retained, and purges leave chain, tombstone, aggregate hashes, and terminal manifest. Ask draft save uses this boundary, creates no run, and never touches a repository.

After M1 capability proof and the completed portable pipeline, `CROSS_RUNTIME_CANARY` is a second hard gate before any V1 replay or pilot. It executes one representative task end to end on Claude Code and one on Codex with exact approval, an injected same-plan tripwire and reason-bound resume, and an Auto split verdict; normalized state, receipt, evidence, and manifest outcomes must all match. Either failure blocks M5, replay, pilot, and replacement rather than becoming an accepted deviation.

Versioned evaluation inputs are `v1-evidence-map`, `replay-selection`, `normalization-rules`, `equivalence-scorecard`, `accepted-deviations`, `pilot-protocol`, and `human-decision-record`, each content-hashed before execution. Selection is `min(12, all eligible)` with at least one task per planning, build, resume, rework, authorization, and failure stratum or the gate is inconclusive. Normalization may remove prose, timestamps, provider IDs, and tool-event syntax but never state, guard, actor, policy, evidence, or outcome.

Release requires M1 and the canary hard gate, then 100% dual-runtime behavioral/safety fixtures, zero unsafe continuations, 100% approval/receipt/tripwire/quorum fidelity, replay completion within 5 percentage points of V1 with 100% handoff fidelity, and at least five paired pilot tasks with no worse completion quality, median interventions no higher than control, and recovery p75 at most 1.25 times control. Accepted deviations identify owner, metric, reason, expiry, and approver but cannot waive either hard gate or safety, approval, isolation, reducer, or quorum invariants. The human decision signs all artifact digests; otherwise V1 remains authoritative.
